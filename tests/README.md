# Тестовете, обяснени просто

## С какво да започнеш

`npm run test:basic` изпълнява 20 примера за роли, обобщения и частичен анализ. Те използват кратки текстове и mock AI отговори, затова са добър първи прочит.

Всеки тест има три стъпки:

1. Подготвяме примерен текст или файл.
2. Извикваме функцията или изпращаме заявка към локален тестов сървър.
3. С `assert.equal`, `assert.match` или `assert.deepEqual` сравняваме резултата с очакваното.

Например `assert.equal(result.status, 'partial')` означава „провери, че анализът е обозначен като частичен“. `assert.rejects` проверява очаквана грешка при асинхронна операция. Тест, който очаква правилно отхвърляне на повреден PDF, е успешен, когато приложението върне съответната грешка.

## Къде да намериш конкретните проверки

| Файлове | Какво проверяват |
| --- | --- |
| `actors.test.js` | Ролята присъства в цитата; няма готов речник с разрешени роли. |
| `summary.test.js`, `insights.test.js` | Обобщения, предупреждения и подредени действия. |
| `partial-validation.test.js`, `quote-resolver.test.js` | Невалиден срок и безопасно възстановяване на интервали. |
| `analysis.test.js`, `validation-diagnostics.test.js` | Схема, срокове и диагностика без тайни данни. |
| `upload.test.js`, `photo.test.js` | Истинско PDF извличане и OCR, размер и формат на файла. |
| `analysis-pipeline.test.js`, `analyze-endpoint.test.js` | Процесът от текст/PDF до проверен mock резултат. |
| `ai-client.test.js`, `gemini-client.test.js` | Подменен HTTP клиент, timeout и откази на доставчика. |
| `browser.test.js`, `analysis-ui.test.js` | Интерфейсът в малка симулирана DOM среда, включително печат. Това не е визуален браузърен тест. |
| `release.test.js` | `/health`, HTTP заглавки и недостъпност на частни файлове. |

`helpers/server.js` стартира и затваря тестов сървър, а `helpers/pdf.js` и `helpers/photo.js` подготвят примерни файлове. Така самите тестове остават по-кратки.

## Команди

```bash
npm run test:basic
npm test
node --test tests/actors.test.js
```

На PowerShell при блокирано npm използвай `npm.cmd`. Не са нужни API ключове. Не изтривай граничните проверки, за да намалиш броя тестове: те пазят ограниченията и правилното поведение при грешка.
